# 역할 설계 위임 비교 실험 v1

상태: 설계 완료, 비교 실행 전. 예산과 채택 기준은 제안값이며 검증된 최적값이 아니다.

## 가설과 비교 조건

AI가 대상에서 역할을 설계하면 고정 역할 팀보다 중요한 문제를 더 잘 발견하는가?

| 조건 | 방식 | 역할 선정 |
|---|---|---|
| A | 단일 에이전트 자유 검토 | 역할·관점 지정 없음 |
| B | 단일 에이전트 관점별 검토 | 사례별 고정 관점 3개 |
| C | 독립 리뷰어 3개 + 종합 | B와 동일한 고정 역할 |
| D | 질문 도출 → 역할 설계 → 독립 리뷰어 3개 + 종합 | AI가 3개 설계 |

주 비교는 D−C다. A−B는 관점 지시, B−C는 검토 분리의 효과를 탐색한다. C/D는 역할 선정 외 실행·종합 절차를 같게 유지한다.

고정 역할도 해당 분야에서 합리적인 관점을 사용한다. D에 유리하도록 보안·방법론·접근성처럼 명백히 필요한 관점을 일부러 빼지 않는다. 현재 역할 목록은 설계자가 정했으므로 별도 전문가의 적절성 확인을 받기 전에는 확정된 강한 기준선이라고 주장하지 않는다.

주 실험 C/D는 추가 역할·후속 토론을 끈다. D의 역할 구성 점검은 허용하되 전체 예산에 포함한다. 최신 스킬의 가변 역할 수·추가 라운드는 후속 실험으로 분리한다. D는 스킬 전체 성능이 아닌 역할 선정 효과를 검증한다.

## 입력 자료와 정보 분리

- [사례](../eval/cases.json): 선택 사례의 input만 공통 전달한다. fixed_roles는 B/C에만 전달한다.
- [조건별 프롬프트](../eval/prompts.md): 공통 지시와 해당 단계 지시를 결합한다.
- [평가자 전용 기준](../eval/grading.md): 검토자·역할 설계자·종합자에게 전달하지 않는다.
- [실행 기록](../eval/run-template.json): 한 사례×조건×반복마다 복사한다.

리뷰어는 새 문맥에서 허용된 텍스트만 받는다. 저장소·정답 파일에 접근하지 못하도록 파일 탐색 도구를 끄고 사례를 직접 전달한다. 파일 분리만으로 정보 차단이 보장되지는 않는다. 정답을 읽은 세션은 리뷰어로 재사용하지 않는다.

## 실행 전 고정

모델의 정확한 식별자·제공자·추론 설정·도구 범위·가격과 확인일·스킬 커밋을 기록한다. 모든 단계에 같은 모델을 사용하고 seed는 지원될 때만 기록한다.

파일럿: 6사례×4조건×1회=24개 최종 결과. 본 실험의 출발점: 3회 반복=72개 최종 결과. 표본 수 적정성은 파일럿 분산과 목표 효과 크기로 다시 결정한다. 같은 합성 사례의 반복을 독립된 새 사례로 취급하지 않는다.

사례별 순서: 1 ABCD, 2 BCDA, 3 CDAB, 4 DABC, 5 ABCD, 6 BCDA. 다음 반복은 한 칸씩 회전한다. 실패 기록을 보존하고 모든 조건에 같은 재실행 규칙을 적용한다.

제안 시간 상한은 사례×조건당 10분이다. 다음 두 트랙을 분리한다.

1. 자연 실행: 시간 상한 안에서 사용량을 측정한다. 품질 차이에 자원 차이가 섞임을 명시한다.
2. 예산 통제: 모든 조건에 전체 출력 토큰 상한 8,000을 적용한다. A/B는 단일 호출, C/D는 기획 1,000 + 리뷰어 각 1,500×3 + 종합 2,500으로 배정한다. C는 고정 역할에 질문을 배정하며 역할을 교체하지 않는다. D는 같은 기획 예산에서 역할을 도출한다.

출력 토큰 동일화는 입력 토큰·추론량·가격 동일화를 뜻하지 않는다. 숨은 추론 토큰은 제공자가 제공할 때 별도 기록하며 중복 합산하지 않는다. 도구로 상한을 강제할 수 없으면 예산 통제 트랙이라고 부르지 않는다.

병렬 지연 시간은 기획 시작부터 종합 완료까지의 경과 시간이며 호출 시간의 합과 구분한다. 진행자 오류와 제공자 오류를 구분하고 성공 사례만 선택해서 비교하지 않는다.

## 실행 절차

1. 설정·사례·프롬프트·정답 기준을 버전과 함께 고정한다.
2. 조건 지시와 해당 사례 input만 전달한다. B/C에만 fixed_roles를 추가한다.
3. C/D 리뷰어에게 자기 역할·담당 질문·공통 원문만 준다. 다른 리뷰 결과와 기획자의 예상 결론은 주지 않는다.
4. 종합자는 원문과 첫 리뷰 결과의 근거를 확인하고 중복을 제거한다. 추가 리뷰 호출은 하지 않는다.
5. 원시 출력·최종 출력·호출별 사용량·실패·상한 도달을 기록한다.
6. 평가용 사본에서 조건명·역할 구성·모델명·파일명을 가리고 발견 사항을 공통 형식으로 전달한다. 원본을 보존한다. 문체로 조건을 추정할 수 있으므로 완전한 맹검이라고 주장하지 않는다.
7. 평가자 2명이 독립 채점하고 불일치를 근거로 조정한다. 1명이면 단일 평가자 한계를 표시한다. AI 채점만으로 정답을 확정하지 않는다.
8. 사례별 paired D−C와 전체 요약·비용·실패율을 함께 보고한다. 파일럿에서 통계적 유의성이나 일반적 우월성을 주장하지 않는다.

## 지표와 집계

- 중요 문제 발견률: 치명적·높음 정답 항목 중 발견한 고유 항목 수 / 해당 정답 항목 수. 같은 근본 문제이면 표현·해법이 달라도 인정한다. 안전 사례는 분모 0이므로 N/A.
- 근거 없는 지적 비율: 뒷받침되지 않는 확정적 결함 주장 / 전체 결함 주장. 명시적 조건부 질문은 분모·분자에서 제외한다. 주장 0개면 N/A와 0건을 함께 보고한다.
- 중복 지적 비율: 같은 근본 문제의 초과 반복 항목 / 전체 결함 주장. 주장 0개면 N/A.
- 권고 타당성: 발견별 0(부적절·제약 위반), 1(방향은 맞지만 불충분), 2(문제에 맞고 제약 준수). 발견한 문제에 한정되므로 발견률과 함께 본다.
- 질문 커버리지: 평가 기준의 질문 중 답 또는 판단 불가 근거를 명시한 비율. 역할 이름 일치로 채점하지 않는다.
- 입력·출력·추론 토큰, 가격, 경과 시간, 실패율. 미측정은 null이며 0으로 대체하지 않는다.

중요 문제 발견률은 먼저 사례별 반복 평균을 구한 뒤 안전 사례를 제외한 사례 평균으로 집계한다. 실패 실행의 발견률은 보존된 출력에서 확인할 수 있는 발견만 반영하며 출력이 없으면 0으로 계산한다. 실패율을 별도 제시하고 성공 실행만의 집계는 보조 결과로 표시한다. 실행 자체가 시작되지 않은 누락은 실패와 구분해 미실행으로 남긴다.

근거 없는 지적·중복 비율은 전체 주장 수를 합친 micro 비율과 사례별 원시 건수를 함께 보고한다. 권고 점수는 채점된 권고 평균, 가격·지연 시간은 실행별 중앙값과 범위를 보고한다. D/C 가격 비는 각 조건 중앙 가격의 비이며 분모 0 또는 미측정이면 N/A다. 검토를 실행했으나 주장 0건인 경우를 미실행과 혼동하지 않는다.

정답 목록 밖의 타당한 발견은 별도 기록하고 두 평가자가 확인한다. 기준에 추가하면 모든 조건을 같은 버전으로 재채점한다. 자체 제작 사례와 정답 목록의 편향·불완전성을 명시한다.

## 채택 기준과 후속 실험

파일럿은 실행 가능성·채점 일관성 확인용이다. 본 실험 결과를 보기 전에 채택 기준을 확정한다.

제안: D−C 사례 평균 중요 문제 발견률 +10%p 이상, 근거 없는 지적 비율 악화 5%p 이하, 중앙 가격 1.5배 이하. 가격 미측정이면 비용 충족 여부는 판정하지 않는다. 안전 사례의 오탐·개별 사례 악화도 보고한다. 작은 표본의 기준 통과만으로 우월성을 확정하지 않는다.

후속 실험은 한 번에 하나씩 변경한다: 가변 역할 수, 역할 점검 제거, 추가 검토 1회 허용, 다른 모델 조합.

참고: [Anthropic — Building effective agents](https://www.anthropic.com/engineering/building-effective-agents). 동적 분해·종합 패턴 참고이며 이 스킬의 효과를 입증하는 자료는 아니다.
