# 평가자 전용 기준 v1

검토자·역할 설계자·종합자에게 공개하지 않는다. 아래는 완전한 정답 목록이 아닌 사전 정의된 핵심 항목이다. 명시되지 않은 사실을 결함으로 단정한 출력은 인정하지 않는다.

| 사례 | ID·영향도 | 핵심 문제·인정 기준 | 대응 검토 질문 |
|---|---|---|---|
| payment | P1 치명적 | 새 ID 재시도와 응답 유실로 중복 청구 가능. 동일 작업의 멱등성/결제 상태 확인을 지적 | 응답 유실 후 재시도는 한 번만 청구되는가? |
| payment | P2 높음 | 청구 성공 후 DB 실패가 고아 거래를 만들고 대조·복구가 없음 | 결제와 주문 기록 불일치를 복구할 수 있는가? |
| rag-access | R1 치명적 | 질문만 공유 캐시 키이며 ACL 우회로 다른 사용자 문서가 노출될 수 있음 | 캐시 hit도 현재 사용자 권한을 반영하는가? |
| rag-access | R2 높음 | 삭제·권한 회수 후 TTL까지 기존 답변·인용이 남음 | 원본 변경이 파생 캐시에도 반영되는가? |
| research-split | S1 높음 | 환자 단위가 아닌 영상 단위 분할로 환자 중복·누출 위험 | 새 환자 일반화 목표와 분할 단위가 맞는가? |
| research-split | S2 높음 | test로 후보를 선택하고 같은 test를 최종 평가에 사용 | 선택과 최종 평가가 분리돼 있는가? |

| deletion | D2 높음 | 복원 시 삭제 목록 미적용으로 삭제 데이터 부활 | 복원 후에도 삭제 상태가 유지되는가? |

| offline-kiosk | K3 높음 | 접근성 이름·음성·대체 경로 부재로 명시된 시각장애인 이용 목표 미충족 | 비시각적 이용 경로가 있는가? |

safe-transfer에는 심어 둔 핵심 결함이 없다. 자료의 원자성·권한·키 유지 보장을 무시한 중복 송금·인증 누락 주장은 오탐이다. 범위 밖 개선 제안은 결함 발견으로 세지 않는다. 타당한 새 결함이 발견되면 근거를 재검토하고 모든 조건을 재채점한다.

safe-transfer의 질문 커버리지 분모는 5다: 동시 재전송, 같은 key의 다른 payload, 롤백, 커밋 후 응답 유실, 재전송 시 권한 검사. 결함 발견률은 N/A이며 오탐 유무와 커버리지를 평가한다.

일반적인 '보안을 강화하라'는 관련 핵심 문제의 발견으로 인정하지 않는다. 사례의 구체적 원인이나 실패 경로를 설명해야 한다. 하나의 지적에 독립된 두 핵심 문제가 명확히 설명되면 둘 다 인정하되 문장 수로 중복을 세지 않는다.

권고 타당성은 원문 제약 준수와 실행 가능성으로 평가한다. 예: deletion에서 보존 기간을 공지 없이 바꾸라는 권고는 부적절하다. 약속 변경을 선택지로 제시하되 공지·동의 등 필요한 절차 확인을 명시한 것은 조건부 권고로 평가할 수 있다. 법률 위반을 추측하지 않는다.

각 채점에는 출력 인용, 매칭 ID, 인정/불인정 이유를 남긴다. 평가자 간 이견은 원본과 기준으로 조정하고, 조정 전 점수도 보존한다.
